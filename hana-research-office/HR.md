# 인사 제도 — 성과 평가 및 자동 개선

> 취지: "조직원들의 성과가 좋지 않을 시 **상시로, 자동으로** 개선한다" (대표이사 설립 방침)

## 1. 평가 체계

모든 산출물은 리스크관리팀 QC에서 등급을 받는다.

| 등급 | 기준 | 처리 |
|---|---|---|
| **A** | 지적 사항 없음 또는 경미한 교정 1~2건 | 그대로 발행 |
| **B** | 수정 후 발행 가능한 지적 3건 이상 (출처 누락, 수치 불일치 등) | 수정 후 발행, 기록 |
| **C** | 재작업 필요 (검산 오류, 출처 불명 수치, 논리 결함) | 재작업, 기록, 개선 검토 |

리스크관리팀 자체의 실책(QC 통과 후 발견된 오류)도 동일하게 기록한다.

## 2. 성과 기록

- 기록부: `office/hr/performance-log.md` (서기: 지식관리팀)
- 기록 항목: 날짜 / 산출물 / 담당 팀 / 등급 / 주요 지적 사항
- 기록은 삭제하지 않는다. 개선의 근거 자료다.

## 3. 자동 개선 (사장 직권)

다음 트리거 발생 시 사장은 **즉시, 대표이사 승인 없이** 해당 팀의 에이전트 정의(`.claude/agents/<팀>.md`)를 개정한다:

- 트리거 1: **C등급 1회** — 결함 원인을 분석해 재발 방지 지침을 에이전트 정의에 추가
- 트리거 2: **동일 유형 지적 2회 반복** (예: 출처 표기 누락 반복) — 해당 항목을 에이전트 정의의 체크리스트로 승격
- 트리거 3: **B등급 3회 연속** — 에이전트 정의 전면 재검토

개정 절차:
1. 결함의 근본 원인 진단 (지시가 모호했는가, 체크리스트가 없었는가, 역할 정의가 틀렸는가)
2. 에이전트 정의 파일 수정 (개정 이유를 커밋 메시지에 명기)
3. 성과 기록부에 개정 사실 기재
4. 다음 보고 시 대표이사께 사후 보고

## 4. 조직 개편

- 기존 팀 R&R에 맞지 않는 업무가 **2회 이상** 발생하면 사장은 신규 부서 설립을 검토한다.
- 설립 시: `.claude/agents/`에 정의 추가 → `ORGANIZATION.md`·`README.md` 조직도 갱신 → 대표이사 보고.
- 3개월(또는 산출물 20건)마다 조직 전체 회고를 실시하고 결과를 `office/hr/`에 남긴다.
